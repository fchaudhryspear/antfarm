## Required v0.16 Changes

1. Add executable tenant-scoped table enforcement.
   - Update migration artifacts so tenant-scoped tables enforce `tenant_id TEXT NOT NULL REFERENCES factory_tenants(id)`.
   - Add validation using `PRAGMA table_info`, `PRAGMA foreign_key_list`, and `PRAGMA foreign_key_check`.

2. Enforce audit-global event typing beyond `factory_system_events`.
   - Add `factory_tenant_audit_log` enforcement for tenant-required event types.
   - Decide how `factory_dashboard_sessions` maps into the event-type matrix or reclassify it.
   - Add `dashboard_scope_missing` and `dashboard_scope_mismatch`, or revise dashboard specs to use one canonical event type.

3. Correct RTBF key-destruction semantics.
   - Pick a precise AWS KMS-compatible key model.
   - Align RTBF states and deletion-proof language with the chosen model.
   - Add CloudTrail/KMS or signed application proof requirements.

4. Resolve `restore_antfarm_snapshot` authority.
   - Recommended: remove from Day2 Ops post-timeout preauthorization.
   - Alternative: make it founder-approved break-glass with immutable manifests, RTBF/legal-hold preservation checks, and externalized audit evidence before restore.

5. Resolve runtime activation gate semantics.
   - Either runtime activation blocks freeze/Phase A, or it is only a Phase C operational gate.
   - Update Sections 4, 12, 13, and 14 so the gate is not simultaneously checked off, open, and non-blocking.

6. Clarify dashboard aggregate behavior.
   - Rename v3.1 capability to cross-tenant ledger metadata view.
   - Reserve federated content search for v3.2+.
   - Define aggregate route/API shape and aggregate action behavior.

7. Sweep stale Day2 Ops timing language.
   - Replace "goes live in 1-2 weeks" and "targeted for Phase A/B" with planned-but-pending activation language tied to the Section 10.3 activation gate.

8. Protect `factory_system_events` as append-only.
   - Add UPDATE/DELETE protections or equivalent enforced append-only writer.
   - Add validation cases for mutation attempts.

9. Fix stale RTBF table name.
   - Use `factory_rtbf_requests` for the table.
   - Keep `rtbf_requests` only as the action type.
